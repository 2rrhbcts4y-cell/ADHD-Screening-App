# Sahel Clinic — ADHD Screening & Referral Support Platform

M.Sc. E-Health capstone project. A **non-diagnostic** AI-assisted ADHD
screening and referral support platform for the Nigerian pediatric context
(ages 4–15), built on the methodology described in the accompanying capstone
notebook (synthetic training data, Random Forest classifier, localized
referral pathways to Nigerian teaching hospitals).

> **Clinical scope**: This system screens for ADHD *risk* and supports
> referral decisions. It does **not** diagnose ADHD. Only a qualified
> psychiatrist, pediatrician, or clinical psychologist can confirm a
> diagnosis.

## Quick start (Docker — recommended)

```bash
docker compose up --build
```

This will:
1. Start Postgres.
2. Build the backend image, **train the Random Forest model at build time**
   (`python -m app.ml.train_model`), and start the API on `:8000`.
3. Build and start the Next.js frontend on `:3000`.

Visit `http://localhost:3000`. Interactive API docs are auto-generated by
FastAPI at `http://localhost:8000/docs` (Swagger UI) and `/redoc`.

## Manual setup (without Docker)

### 1. Backend

```bash
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env        # then edit DATABASE_URL / SECRET_KEY

# Train the model (creates app/ml/artifacts/*.joblib)
python -m app.ml.train_model

# Make sure Postgres is running and DATABASE_URL points to it, then:
uvicorn app.main:app --reload
```

The API will create its tables automatically on startup for this capstone
build. For a real deployment, generate proper Alembic migrations instead of
relying on `Base.metadata.create_all`.

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env.local 2>/dev/null || true   # or just export NEXT_PUBLIC_API_URL
npm run dev
```

Set `NEXT_PUBLIC_API_URL` (defaults to `http://localhost:8000`) if your
backend runs elsewhere.

## Retraining the ML model

The classifier ships trained on **synthetic** data generated by
`backend/app/ml/train_model.py`, following the same simulated-dataset
approach as the source capstone notebook (no real patient data required to
run the project). To regenerate:

```bash
cd backend
python -m app.ml.train_model
```

This overwrites `app/ml/artifacts/adhd_screening_rf_model.joblib` and
`adhd_model_metadata.joblib`. Before any real-world clinical use, this model
must be retrained on properly consented, ethically sourced clinical data and
validated by qualified clinicians.

## Core user flow

1. Parent or teacher registers / signs in.
2. Adds a child profile (age, gender, school level, state).
3. Completes the 18-item DSM-5-aligned questionnaire (9 inattentive + 9
   hyperactive-impulsive items, scored Never(0)–Very Often(4)).
4. Backend computes subscale/total scores, runs the Random Forest model, and
   returns a risk level (Low / Moderate / High) with confidence and a
   localized referral recommendation.
5. User can download a PDF report (reportlab) summarizing scores, risk
   level, and referral pathways (e.g. LUTH, UCH, Federal Neuro-Psychiatric
   Hospital Yaba) for high-risk cases.

## API summary

| Method | Path                              | Description                          |
|--------|------------------------------------|---------------------------------------|
| POST   | `/api/auth/register`              | Create parent/teacher account         |
| POST   | `/api/auth/login`                 | Get JWT access token                  |
| POST   | `/api/children/`                  | Create a child profile                |
| GET    | `/api/children/`                  | List your children                    |
| GET    | `/api/screenings/questionnaire`   | Get the 18-item questionnaire         |
| POST   | `/api/screenings/`                | Submit answers, get AI risk result    |
| GET    | `/api/screenings/child/{child_id}`| Screening history for a child         |
| GET    | `/api/reports/{screening_id}/pdf` | Download PDF report                   |

Full interactive documentation: `/docs` (Swagger) and `/redoc` once the
backend is running.

## Security notes for production

- Replace `SECRET_KEY` with a long random value and keep it out of source
  control.
- Put the API behind HTTPS (e.g. via a reverse proxy / managed load
  balancer).
- Use Alembic migrations instead of `create_all` once the schema stabilizes.
- Add rate limiting on `/api/auth/login` to slow brute-force attempts.
- Review data-retention and consent requirements for child health data under
  Nigeria's NDPA (Nigeria Data Protection Act) before any real deployment.

## Deployment suggestions

- **Backend**: any container host (Render, Railway, Fly.io, AWS ECS/Fargate).
  Point `DATABASE_URL` at a managed Postgres instance (Render/Neon/RDS).
- **Frontend**: Vercel (native Next.js support) or the same container host;
  set `NEXT_PUBLIC_API_URL` to your deployed backend's public URL.
- **Database**: managed Postgres (Neon, Render Postgres, AWS RDS).
